# 파서와 과목 판정 규칙

`AGENTS.md`에서 옮긴 세부 규칙이다(2026-11-02). 파서, 과제명, 과목 구간, 과목 판별, 교사 이름 가리기를 고치기 전에 읽는다.
새로 정한 세부 규칙도 `AGENTS.md`가 아니라 이 문서에 더한다.

## 과목 추가와 판별

  과목을 늘릴 때 고칠 곳: `scripts/biology_subject_aliases.py`(본문 판별), `build_biology_assessment_manifest.py`(파일 이름),
  `build_strict_biology_shortlist.py`(성취기준 코드 뼈대), `build_school_subject_assessment_catalog.py`(교육과정 묶음),
  `biology_assessment_detail_parser.py`의 `EXPECTED_STANDARD_PREFIXES`(과목 구간·코드 판정), API `repository.py`의 `SUBJECT_ORDER`.
  이미 합친 차수에 과목을 더할 때는 그 차수를 넓힌 범위로 다시 만들고 `merge_publish_dbs.py --subject`로 새 과목만 가져온 뒤
  `refresh_biology_assessment_details.py`로 전체 상세를 다시 만든다(2026-10-31 세포와 물질대사·생물의 유전·통합과학2·과학탐구실험2 추가).
  - 2026 1학년(2022) 계획은 "통합과학 1", "과학탐구실험Ⅰ"로 쓰고 제목에서 "[과학탐구실험]"으로 줄인다. 그래서 맨이름
    통합과학·과학탐구실험은 그 문서에 2022 번호 과목(이름 또는 `[10과탐1-…]` 코드)이 없을 때만 2015 과목이다
    (`subject_hits`). 2015 모양 코드 `[10통과01-01]`은 학교가 2022 계획에도 옮겨 쓰므로 2015의 근거가 아니다.
    색인은 번호 과목 위치를 표기 순서(붙인 "통합과학1" → "통합과학 1"/"통합과학Ⅰ" → 줄임 제목)로 찾고, 줄임 제목
    위치의 기록도 하나 더 내서 엄격 후보 단계가 나은 쪽을 고른다(목차 "# 6. 통합과학 1"이 계획보다 먼저 잡히지 않게).
    엄격 후보 단계는 번호 과목에서 옛 꼴 코드와 "( 과학탐구실험1 )과 교수학습" 제목도 근거로 친다.
  - 파서(`parse_assessment_section`): 번호 과목을 보통대로 읽어 공개 과제가 하나도 없을 때만 다시 읽는다. 다시 읽을
    때는 그 과목 이름으로 연 구간에서 옛 꼴 코드도 그 과목으로 치고, 문서에 다른 번호 과목(1이면 2)의 이름·코드가
    없으면 줄임 이름 "[과학탐구실험]" 위치와 문서 전체의 옛 코드 행도 그 과목으로 읽는다. 이미 과제가 나오는 계획은
    다시 읽지 않는다 — 옛 코드를 그 과목으로 치자 채점표의 "관련단원"·"같은 족" 줄이 계획 표의 이름을 밀어냈다.
  - 과목 판별을 고친 뒤 이미 합친 차수에 반영할 때는 차수를 다시 만들어 (문서 sha256, 과목) 단위로 옛 카탈로그와
    비교하고, 고친 규칙 때문에 생긴 사례만 더하고 사라진 사례만 뺀다. 사례 ID(저장 경로 기준)로 비교하면 같은
    문서가 다른 경로로 잡힌 것까지 바뀐 것으로 보인다.

## 원문 표 세 층과 재생성 순서

- 원문 표는 세 층으로 본다(2026-10-30 kordoc 전환).
  1. 추출: `scripts/extract_kordoc_documents.py`가 `tools/kordoc/worker.mjs`(kordoc 버전 고정)로 원문을
     블록 구조(셀 격자·병합 칸·셀 속 표)로 읽어 `data/derived/kordoc/`에 저장한다. 표를 글로 뭉개지 않는다.
  2. 흐름: `scripts/kordoc_flow.py`가 틀 표를 풀고, 제목 상자를 제목으로, 칸 속 큰 표(루브릭)는
     바깥 표 뒤로 꺼내고, 작은 메뉴 표는 칸 글로, `□V`는 `☑`로 바꿔 파서 입력 텍스트를 만든다.
     파서에 들어가는 표에는 중첩 표가 없다. 규칙을 고치면 `test_kordoc_flow.py`에 실제 모양 테스트를 넣는다.
  3. 화면: `apps/biology-assessment-web/app/lib/source-html.ts`는 허용 목록 정화와 표시만 한다.
     행을 옮기거나 표를 합치는 DOM 수술을 다시 넣지 않는다. 표가 이상하면 1·2층을 고친다.
  `markdown_fragment_to_html`은 표를 하나씩 그대로 옮긴다(옛 표 융합 판정은 다음 과제 표를 앞 표에
  붙이는 오류를 내서 지웠다). 데이터 층을 고쳤으면 `scripts/refresh_biology_assessment_details.py
  --evidence-source data/derived/kordoc_evidence_source_2026_1.jsonl`로 상세 표만 다시 만들고
  `npm run audit:data`, `npm run audit:renderer`, `npm run package:vercel`, `npm run stage:vercel`
  순으로 배포 패키지를 갱신한다.

## 과제명과 과목 구간 규칙

- 과제명과 과목 구간 규칙(2026-10-31):
  - 짧은 활동 머리글("1) 동시낙하 실험보고서") 아래 `수행과제` 칸이 할 일을 늘어놓은 설명이면
    머리글이 이름이고 칸은 개요다. 그 설명을 다른 표 추출기가 따로 과제로 다시 싣지 않는다.
  - 점수 칸("70점 (이하)"), 지필고사 범위, "~하였는가?" 채점 질문, 문서 구조 제목(방침·유의 사항·
    정의적 능력 평가 등)은 어느 추출기에서 왔든 과제명이 아니다(`_named_items`가 한 번 더 거른다).
  - 과목 구간은 표지 표의 `과목명 │ 생명과학Ⅱ` 칸, `생명과학2` 같은 숫자 표기, "교수학습·평가 계획"
    같은 제목 변형으로도 찾는다. 숫자 표기를 볼 때 "N학년·N학기"는 지운다("(생명과학)_2학년" ≠ 생명과학Ⅱ).
    변형 제목은 다른 과목명이 들어 있을 때만 구간을 끝낸다.
  - 확정 항목이 모두 그 과목 성취기준 코드만 가지면 과목 제목을 못 찾았어도 경계가 확인된 것이다
    (`subject_code_rows`/`assessment_code_rows`). 공개 게이트는 이것을 신뢰 경계로 센다.
  - 과제명이 아닌 것은 `_not_a_task_name` 한 곳에서 거른다: 교육과정 단원명(`CURRICULUM_UNIT_NAMES`),
    표 라벨·월·횟수·과목명·등급·평가 방식, 문서 절 제목, 방침 문장, 채점 요소("~ 정도/능력/태도"),
    번호 단계("(1) 주제 선정하기"), 교사 라벨("지도교사: …"). 제목줄 후보 단계에는 넣지 않는다 —
    넣으면 단원 제목줄 아래 표가 앞 과제 구간으로 합쳐진다.
  - 다음 과목의 시작은 수준과 상관없이 본다(`_line_opens_other_course`): 학년도로 시작하는 계획서 제목,
    괄호 과목명, "N 과목명 교수학습 … 계획", 다른 과목의 압축 구성원·표지 칸. 과목명 접두("[통합과학]")는
    같은 과목, 학과 파일("과학과 평가계획")은 같은 묶음, 자기 제목 바로 아래 일반 줄의 다른 과목명은
    양식 재사용으로 본다.
  - 같은 과제의 두 표기는 하나로(`_same_task_named`: 오타 한 글자·일반 낱말 차이·꼬리표; 낱말 첫 글자가
    다르거나 번호가 다르면 다른 과제). 남길 표기는 원문에 더 자주 나오는 쪽. 요약표 행은 같은 성취기준
    코드에 내용 낱말 둘을 공유하는 상세 과제가 있으면 그 과제다.
  - 공개 DB에는 교사 이름을 싣지 않는다. `npm run package:vercel`이 먼저 `scripts/mask_teacher_names.py`로
    직책 칭호("지도교사·평가교사·공동 채점교사·교과담당교사") 뒤 이름, 교사 머리글 아래 열(병합 칸·
    "홍길동(사)" 꼬리표 포함), 사례 요약에 " · "(칸)·" / "(행)로 풀린 표의 교사 칸을 "○○○"로 가리고,
    배포 검사가 제목의 교사 라벨과 모든 항목 원문에 남은 이름을 막는다. 표 머리글 낱말(성취도·교무부장·
    과목명)은 이름으로 보지 않는다. kordoc 원문(로컬)은 그대로 둔다. 테스트의 이름은 데이터에 없는
    지어낸 이름만 쓴다. 2026-10-31 새 과목 추가 때 더한 양식: 제목과 이름이 다른 문단(`<p>1. 담당교사</p><p>이름</p>`),
    `지도교사(강사)`, `담당교사 :` 칸 다음 칸, 이름마다 붙은 꼬리표(`(1학년)`·`(국악과)`), 풀린 행 끝까지 띄어 쓴
    이름들, `보충지도 수업 교사`, 일화기록 서식의 `기록: 교사 이름`, "이수"로 시작하는 이름(이수학점과 구분).
    데이터를 크게 늘리면 가린 사본에서 교사 낱말 바로 뒤(12자 안)에 남은 성씨+두 글자 낱말을 드문 것부터
    직접 읽어 새 양식을 찾는다(교과서 저자 칸 "조철기 외 12명" 같은 공개 저자명은 둔다).
  - 과목 판정은 앞부분 맞추기로 하지 않는다(2026-11-01 전수 감사에서 350건 오분류). 과목명은 낱말 단위
    (`_names_course`: 뒤에 숫자·Ⅰ·Ⅱ·실험이 붙거나 앞에 "고급"이 붙으면 다른 과목), 성취기준 코드는 가장 긴
    접두를 가진 과목 것이다(`12생과Ⅱ`는 생명과학Ⅱ, `10통과1`은 통합과학1, `[12생과II…]`는 Ⅱ로 읽는다).
    2015 통합과학·과학탐구실험은 2022 코드를 형제로 받지 않는다. 확정 항목의 마지막 관문
    `_names_another_course`는 코드가 전부 다른 과목 것이거나 항목 안 "과목 │ X" 칸이 다른 과목이면 공개에서 내린다.
  - `_finish_item`: 표 없이 제목·소제목뿐인 구간, "아래의 채점 기준표"만 가리키는 구간은 내리고, 머리줄만 남은
    루브릭은 비우고, 100을 넘는 반영 비율("405")은 비운다. 배점·반영 칸(`_score_only`)은 채점 단계 점수 나열
    ("35 32 29 26 23 20")을 비우고, 같이 읽힌 채점 문장·성취기준·기본점수 안내·양식 문구는 빼고 점수만 남긴다
    ("…설명할 수 있다. · 25점" → "25점"). "총 20점 · 서술·논술 15점"처럼 학교가 적은 점수 내역은 둔다.
  - 2026-11-01에 더한 과제명 규칙: 라벨·번호 접두("과정중심 수행평가 영역1:", "항목2 :", "수행과제 1 -",
    "수행평가 세부계획 5-1.", 표 칸의 "2. "), 번호 라벨 뒤 괄호 속 이름("수행평가 영역2(…)", "4순위 수행평가 (…)"),
    괄호째 점수·비율("(각 15점, 총 30점)"), 잘린 끝("반응(", "실험 및"), 단계까지 이어 쓴 칸은 첫 활동만,
    학교의 `<생명공학기술>` 꺾쇠는 글로 둔다. 과제명이 아닌 것: 평가 목표·유의점·주안점·정기시험·환산 점수·
    통합학급·디지털 환경 같은 절 제목, 양식 안내("※…편집하여 작성※"), 탐구 단계 줄("문제인식 및 가설설정",
    "결론도출"), "~하였는가?" 채점 물음, 평가 요소 명사("관련성", "전달력"), 역량 나열, 지필 요약표 열("논술형",
    "서술형5)"), 교사별 시기표, "8월~11월", 한자 섞인 깨진 글자. "자료해석"·"탐구 설계"처럼 학교가 영역 이름으로도
    쓰는 말은 규칙으로 막지 않는다 — 채점표 줄인 사례만 아래 검토 목록에 적는다.
  - 배포 전 `npm run clean:data`(배포 준비의 첫 단계)가 발행 DB를 정리한다: `normalize_symbol_glyphs.py`(윙딩스·한컴
    기호 글꼴의 사용자 영역 글자를 □☑·숫자로), `apply_title_review.py`(아래 검토 목록을 다시 적용),
    `dedupe_publish_cases.py`(같은 학교 공시의 다른 첨부·차수로 두 번 들어간 같은 계획은 최신 차수·첨부 하나만).
  - 규칙으로 가르지 못하는 사례별 판단(상위 과제가 옆에 있을 때만 채점 요소인 것, 다른 말로 쓴 같은 과제)은
    `scripts/review/title_review.csv`에 적고, 발행 DB 빌드가 그 항목을 확정에서 검토 필요로 내린다(지우지
    않는다). 2026-10-31 소넷 전수 점검(1,211건 표시)에서 규칙으로 처리하고 남은 241건이 들어 있다.
  - 규칙을 고친 뒤에는 `scripts/compare_parser_with_publish_db.py`로 모든 사례를 다시 읽어 발행 DB와
    비교하고(8프로세스 약 5분, 색인은 `data/derived/kordoc_offsets_2026_{1,3}.json`), 확정이 빠진 사례와
    새로 확정된 사례, 이전 비교에서 사라진 제목을 직접 본다. 규칙을 넓힐 때마다 진짜 과제를 지운 적이
    있다(요약표 행 개수 규칙, "과학의 "로 시작하는 줄, 과목명 줄임 "[통합과학]").
    이 도구는 검토 목록과 빌드 단계를 적용하지 않아 발행 DB와 바로 비교하면 차이가 많다. 고치기 전 파서를
    따로 꺼내 같은 도구로 한 번 돌려 두고 파서끼리 비교하면 규칙 변화만 남는다(v2 원문 색인은
    `data/derived/kordoc_offsets_2026_{1,3}_v2.json`). 2026-11-01에 이렇게 잡은 회귀: 괄호 학년 "(2)학년",
    꺾쇠 줄 "※ <교수학습 및 평가방법>은…"이 다음 과목 제목으로 읽힘, 양식 재사용 "과목명 │ 생명과학Ⅰ" 칸에서
    구간이 끊김, 구조 제목 목록에 넣은 줄이 머리글 경계를 잃게 함. 재생성 중인 작업을 멈출 때는 파이썬
    프로세스까지 끝났는지 확인한다 — 남은 프로세스가 같은 출력 DB에 쓰면 "malformed"가 난다.
- 추출원을 바꾸거나 파서를 크게 고치면 `scripts/compare_extraction_sources.py`로 같은 파서·두 원문을
  전수 비교한다(항목 수 증감과 표 품질 지표). 줄어든 사례는 하나씩 열어 본다.
